# Continuous integration foundation

Date: 2026-10-01. DEV-D4/DEV-D8 technical infrastructure for the implementation plan's build, test, migration and regression gates. This adds no product scope, database tables or authorization rules.

## Workflow

`.github/workflows/ci.yml` runs on pushes, pull requests and manual dispatch. Two independent Ubuntu 24.04 jobs provide:

1. **Build, migrations and tests**: workflow lint; locked NuGet restore; full Release build; xUnit unit and real PostgreSQL integration tests; pinned EF tool restore and pending-model-change detection; locked frontend install; formatting, production build and Angular unit tests; locked Playwright install; mocked failure tests; Release-built real API/PostgreSQL browser harness.
2. **Packaged application smoke test**: build API/SPA/migration images, create an isolated PostgreSQL project, apply migrations twice, verify HTTP/error contracts and runtime restrictions, and run production-SPA desktop/mobile browser checks. The existing smoke script performs scoped cleanup.

Both jobs have 30-minute limits. Superseded runs on the same ref are cancelled. A failing command fails its step/job; no test uses `continue-on-error` or is replaced by an in-memory database. No path filters suppress security/build checks for selected changes.

## Security boundaries

- Only `contents: read` is granted; checkout does not persist credentials. There are no repository secrets, deployment keys, OpenAI keys, SMTP credentials or remote publication steps. The workflow uses `pull_request`, not a privileged untrusted-code trigger.
- GitHub-maintained checkout/.NET/Node setup actions use full commit SHAs verified against their release tags. This follows the [GitHub Actions secure-use guidance](https://docs.github.com/en/actions/reference/security/secure-use). Action updates require review and revalidation; pinning alone is not a vulnerability audit.
- The workflow validator image is digest-pinned and runs without networking against a read-only repository mount, with dropped capabilities and a read-only root filesystem.
- Dependency installs use NuGet lock enforcement and `npm ci`. Node 22.22.3/npm 11.6.2 match the application toolchain; the .NET version comes from `global.json`. No shared dependency/build cache is configured in this initial workflow.
- Test credentials are generated by disposable harnesses. Real-auth traces/videos remain disabled, and the workflow does not upload environment dumps, databases or browser network artifacts. Only ordinary test/build console output is retained by GitHub's normal run logs.
- PostgreSQL tests use PostgreSQL 18 containers, not the runner's installed database. The [Ubuntu runner image inventory](https://github.com/actions/runner-images/blob/main/images/ubuntu/Ubuntu2404-Readme.md) lists Docker, Compose and PowerShell required by these jobs. Do not move untrusted PR execution to a persistent/self-hosted runner without a separate security review.
- Normal cleanup removes the generated test resources. Hosted runner disposal bounds resource lifetime if a job is cancelled before cleanup completes. Local scripts still require their scoped cleanup; never substitute broad Docker volume pruning.

To lint locally with Docker from PowerShell at the repository root:

```powershell
docker run --rm --network none --read-only --cap-drop ALL --security-opt no-new-privileges --tmpfs /tmp -v "${PWD}:/repo:ro" -w /repo rhysd/actionlint:1.7.12@sha256:b1934ee5f1c509618f2508e6eb47ee0d3520686341fec936f3b79331f9315667 -color .github/workflows/ci.yml
```

The test/build commands in the workflow also run locally with the prerequisite toolchains. On Windows, use the documented Docker Desktop endpoint for Testcontainers if necessary; do not copy a Windows `DOCKER_HOST` into the Ubuntu workflow.
